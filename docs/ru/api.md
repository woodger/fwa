# Публичный API

[English](../api.md) | Русский | [简体中文](../zh/api.md)

Программный API доступен из корня пакета:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd()
});
```

`runSuite` синхронно читает конфигурацию и проверяет скомпилированные тесты,
запускает поток нативного тест-раннера и возвращает `void` после подключения к
потоку. Функция не возвращает `Promise`, поэтому ожидать завершения набора тестов
через `await` нельзя. Этот API совместимости используется CLI.

Для оркестрации используйте двухфазный API:

```ts
import {
  prepareSuite,
  runPreparedSuite
} from 'fwa';

const plan = prepareSuite({
  projectDir: process.cwd(),
  prune: true
});

const result = await runPreparedSuite(plan, {
  onEvent: (event) => {
    if (event.type === 'summary') {
      console.info(event.data);
    }
  }
});

if (result.status === 'failed') {
  // Оркестратор сам решает, как этот набор влияет на общий запуск.
}
```

`prepareSuite` разрешает TypeScript-проект, находит скомпилированные тесты и
проверяет устаревшие результаты сборки, не запуская тесты и не изменяя
`process.exitCode`. Функция возвращает `SuitePlan` с разрешёнными каталогами и
списком тестовых файлов. Опции подготовки отвечают за разрешение проекта,
удаление устаревших файлов, исключение файла раннера и диагностические сообщения.
Опции выполнения,
например `isolation` и `nodeArgs`, принадлежат `runPreparedSuite`: они намеренно
не принимаются `prepareSuite` и не сохраняются в плане.

`runPreparedSuite` выполняет подготовленный снимок. Для пустого плана
возвращается `{ status: 'empty', exitCode: 1 }`, а тест-раннер Node.js не
запускается.

Для обычного однопроходного сценария используйте `runSuiteAsync`:

```ts
import { runSuiteAsync } from 'fwa';

const result = await runSuiteAsync({
  projectDir: process.cwd(),
  output: process.stdout
});
```

`runSuiteAsync` эквивалентен подготовке с последующим выполнением и возвращает
`Promise<SuiteRunResult>`. Ошибки конфигурации и подготовки отклоняют Promise.
Падения тестов разрешают Promise с `status: 'failed'`; ошибки раннера, репортера
и выходного потока отклоняют его. Результат содержит `testFiles`,
счётчики тестов, длительность выполнения и значение `exitCode`, которое может
использовать оркестратор.

Асинхронный API предназначен для библиотечного использования: он не выводит
данные репортера без явно переданного `output` и никогда не изменяет
`process.exitCode`. Владельцем переданного выходного потока остаётся вызывающий
код: `fwa` ожидает завершения записи репортера, но не закрывает поток.

Текущий запуск можно отменить через `AbortSignal`:

```ts
const controller = new AbortController();

const resultPromise = runSuiteAsync({
  projectDir: process.cwd(),
  signal: controller.signal
});

controller.abort();

const result = await resultPromise;
```

Отмена представляется как завершённый неуспешный запуск: Promise разрешается с
`status: 'failed'`, `exitCode: 1` и количеством отменённых тестов. Только факт
вызова `abort` не отклоняет Promise. Ошибки нативного раннера или потока
по-прежнему приводят к отклонению.

Четыре показанные функции и экспортируемые из корня пакета TypeScript-типы
составляют публичный API. Внутренние файлы в `dist` являются деталями реализации.

## Конфигурация TypeScript-проекта

Через `tsConfigPath` можно выбрать конфигурационный файл или каталог с
`tsconfig.json`:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd(),
  tsConfigPath: 'tsconfig.test.json'
});
```

Опция принимает файл или каталог так же, как `tsc --project`. Относительные
пути разрешаются от `projectDir`.

Парсинг конфигурации является внутренней ответственностью `fwa`. Вызов
`runSuite` не загружает и не ограничивает пакет `typescript`
проекта-потребителя.

## Удаление устаревших файлов

Опция `prune` удаляет скомпилированные тесты, исходники которых больше не
существуют:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd(),
  prune: true
});
```

По умолчанию удаление отключено.

Для безопасности настроенный `outDir` должен быть отдельным каталогом внутри
`projectDir`.

Если `--prune` удаляет все найденные тесты, файлы всё равно удаляются, после чего
раннер сообщает о пустом наборе тестов через `log` и устанавливает
`process.exitCode = 1`.

## Диагностический вывод

Через `log` можно получать сообщения подготовки без замены `console.warn`:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd(),
  log: (message) => {
    console.info(message);
  }
});
```

Функция обратного вызова получает сообщения об успешном удалении и пустом наборе
тестов. Ошибки,
мешающие разрешить выбранную конфигурацию TypeScript, её цепочку `extends` или
пути `rootDir` и `outDir`, выбрасываются так же, как ошибки устаревших
скомпилированных тестов. Остальные диагностические сообщения TypeScript остаются
ответственностью сборки проекта-потребителя. В асинхронном API используйте `log`
для сообщений подготовки, а `output` или `onEvent` — для вывода выполнения.

`onEvent` получает нормализованные события `pass`, `fail`, `summary`, `stdout` и
`stderr`. Поле `data` сохраняет данные соответствующего нативного события
`node:test`. При изоляции процессов версии Node.js с нативными событиями
`summary` могут отправить сначала `summary` отдельного файла, а затем общий
`summary`. На поддерживаемых версиях без нативных событий `summary` `fwa`
формирует одно совместимое общее событие после завершения и самостоятельно
измеряет прошедшее время. Исключение из `onEvent` отклоняет Promise запуска.

## Исключение файла раннера

`runnerFile` исключает один JavaScript-файл из найденного списка тестов. Опция
предназначена для пользовательских CLI или точек входа bootstrap, которые
могут сами оказаться внутри целевого `outDir`.

Обычным пользователям программного API эта опция не нужна. Если она необходима,
предпочтителен абсолютный путь; при исключении относительные значения следуют
текущему рабочему каталогу процесса.

## Опции тест-раннера Node.js

`runSuite` использует исполняемый файл текущего процесса Node.js. Функция не
принимает путь к внешнему Node.js и не управляет другой версией среды выполнения.

При `isolation: 'process'` нативный тест-раннер запускает дочерние процессы на
текущей версии Node.js. При `isolation: 'none'` тесты выполняются в текущем
процессе. `nodeArgs` изменяет только флаги, передаваемые изолированным дочерним
процессам.

Вызов `runSuite` подтверждает поведение только в текущей среде выполнения.
Совместимость
с другими версиями Node.js должна проверяться отдельно CI-матрицей
проекта-потребителя.

Отключение изоляции процессов:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd(),
  isolation: 'none'
});
```

Для явно настроенной опции `isolation` требуется Node.js `>=22.8.0`.

Передача флагов Node.js изолированным дочерним процессам:

```ts
import { runSuite } from 'fwa';

runSuite({
  projectDir: process.cwd(),
  nodeArgs: [
    '--no-warnings',
    '--conditions=development'
  ]
});
```

Для `nodeArgs` требуется Node.js `>=22.10.0`. Опцию нельзя использовать вместе
с `isolation: 'none'`.

## Ошибки и код завершения

API совместимости `runSuite` синхронно выбрасывает ошибки конфигурации и
валидации вызывающему коду.

Во время выполнения набора тестов через API совместимости `fwa` не вызывает
`process.exit()`
напрямую. При падении теста или отсутствии доступных для запуска тестов он
устанавливает:

```ts
process.exitCode = 1;
```

Падения тестов сообщаются после возврата из `runSuite`, поскольку выполнение
нативных тестов основано на потоках. Асинхронный API оркестрации оставляет
политику кода завершения вызывающему коду и возвращает тот же результат через
`SuiteRunResult`.

## Текущий рабочий каталог

`projectDir` управляет разрешением конфигурации и поиском скомпилированных
тестов. Нативный тест-раннер Node.js всё равно запускается в контексте текущего
процесса вызывающего кода: API временно не вызывает `process.chdir` и не
изменяет окружение для отдельного набора тестов. Оркестратор, которому нужен
другой рабочий каталог или окружение, должен запускать `fwa` в отдельном
изолированном рабочем процессе.

## Источник истины

Поверхность публичного API определяется следующими файлами:

- `src/index.ts`
- `src/application/run-suite.ts`

Этот документ описывает использование. Точная форма опций определяется
экспортируемыми TypeScript-декларациями.
