# Конфигурация TypeScript

[English](../typescript-config.md) | Русский

`fwa` читает каталоги исходников и результата сборки из конфигурации TypeScript
целевого проекта.

По умолчанию используется:

```text
<project-root>/tsconfig.json
```

Поиск по умолчанию не поднимается в родительские каталоги. Если конфигурация
находится в другом месте, укажите `--project` явно.

`fwa` не объявляет TypeScript как peer dependency и не загружает пакет
`typescript` проекта-потребителя. Версия компилятора остаётся под управлением
этого проекта.

Пути разрешаются специализированным лёгким парсером, используемым только
`fwa`. Благодаря этому поведение раннера не зависит от изменений API TypeScript
в графе зависимостей потребителя и не требует поставки компилятора как
runtime-зависимости.

С помощью `--project` можно выбрать другой конфигурационный файл или каталог с
`tsconfig.json`:

```sh
fwa --project tsconfig.test.json
fwa ./packages/example --project tsconfig.test.json
```

`--project` принимает файл или каталог так же, как `tsc --project`.

## Опции компилятора

`compilerOptions.outDir` обязателен, поскольку `fwa` запускает
скомпилированные JavaScript-тесты. Без `outDir` раннер не может однозначно
определить расположение результата сборки.

`compilerOptions.rootDir` необязателен. Если он отсутствует, `fwa` считает
корнем исходников каталог, содержащий `tsconfig.json`.

Для стабильного сопоставления исходников и результата сборки рекомендуется
указывать `compilerOptions.rootDir` явно. Обычно это `"src"` или `"."`.

`fwa` разрешает `extends`, а также относительные пути `rootDir` и `outDir` в
соответствии с поведением конфигурации TypeScript.

Раннер не проверяет остальные опции компилятора, не перечисляет исходные файлы
и не выполняет проверку типов проекта. Эти проверки принадлежат сборке
проекта-потребителя и должны завершиться до запуска `fwa`. При этом выбранная
конфигурация и её цепочка `extends` должны быть доступны, синтаксически корректны
и разрешимы. Указанный `compilerOptions.rootDir` и обязательный
`compilerOptions.outDir` должны разрешаться в строки путей.

## Ожидаемая структура

Относительный путь от `rootDir` до исходного теста должен совпадать с
относительным путём от `outDir` до скомпилированного теста.

Пример:

```text
src/feature/example.test.ts
dist/feature/example.test.js

src/feature/example.spec.ts
dist/feature/example.spec.js
```

Поддерживаются файлы `.test` и `.spec`:

```text
source:   *.test.ts, *.spec.ts
compiled: *.test.js, *.spec.js
```

## Источник истины

Поведение во время выполнения реализовано в следующих файлах:

- `src/infrastructure/tsconfig-parser.ts`
- `src/infrastructure/tsconfig-directories.ts`
- `src/bootstrap/suite.ts`

Этот документ описывает использование. Точный контракт парсинга определяется
кодом и тестами.
