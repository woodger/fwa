# Использование CLI

[English](../usage.md) | Русский | [简体中文](../zh/usage.md)

`fwa` — это CLI-обвязка над нативным `node:test` для запуска
скомпилированных TypeScript-тестов.

Он не компилирует TypeScript и не заменяет `node:test`. Раннер читает
конфигурацию TypeScript целевого проекта, находит скомпилированные
JavaScript-тесты, проверяет их соответствие исходным TypeScript-тестам и
передаёт итоговый список файлов нативному тест-раннеру Node.js.

Раннер не ограничивает версию TypeScript в проекте и не загружает пакет
`typescript` проекта-потребителя.

## Среда выполнения Node.js

`fwa` запускает скомпилированные тесты тем же исполняемым файлом Node.js,
которым запущен CLI. Он не выбирает, не загружает и не управляет другой версией
Node.js.

При изоляции `process`, используемой по умолчанию, нативный тест-раннер запускает
дочерние процессы на текущей версии Node.js. При изоляции `none` тесты
выполняются в текущем процессе. `--node-args` передаёт флаги изолированным
тестовым процессам, но не выбирает другой исполняемый файл.

Самому `fwa` требуется Node.js `>=20.19.0`. Поэтому успешный прогон подтверждает
поведение только на текущей версии Node.js. Поддержку других версий, включая
версии ниже указанного для `fwa` диапазона `engines`, проект-потребитель должен
проверять отдельно в задачах совместимости или smoke-тестах своей CI-матрицы.

## Рекомендуемый скрипт

```json
{
  "scripts": {
    "build": "tsc",
    "test": "fwa"
  }
}
```

Запуск:

```sh
npm run build
npm test
```

При использовании `fwa` из другого npm-пакета вызывайте команду `fwa`, а не
файлы внутри `dist`.

## Основные команды

Запустить тесты для текущего рабочего каталога:

```sh
fwa
```

Запустить тесты для другого корня проекта:

```sh
fwa ./packages/example
```

Выбрать конфигурацию TypeScript:

```sh
fwa --project tsconfig.test.json
fwa -p tsconfig.test.json
fwa ./packages/example --project tsconfig.test.json
```

Удалить устаревшие скомпилированные тесты без соответствующих исходников:

```sh
fwa --prune
```

Передать флаги Node.js изолированным тестовым процессам:

```sh
fwa --node-args --no-warnings --conditions=development
fwa ./packages/example --node-args --no-warnings
```

`--node-args` должен быть последней опцией `fwa`, поскольку все последующие
аргументы передаются тестовым процессам Node.js.

## Опции

```text
Usage: fwa [project-root] [options]

Options:
  -p, --project <path>     TypeScript config file or directory.
  --prune                  Prune stale compiled tests without source.
  -i, --isolation <mode>   Test isolation: process or none. Default: process.
  --node-args <args...>    Pass remaining args to Node test processes.
  -h, --help               Show help.
  -v, --version            Show version.
```

Правила:

- без позиционного корня проекта используется текущий рабочий каталог;
- допускается не более одного позиционного корня проекта;
- `--project` можно указать только один раз;
- значение `--project` передаётся отдельным аргументом:
  `--project tsconfig.test.json`;
- `--project` принимает путь к конфигурационному файлу или каталогу с
  `tsconfig.json`;
- `--project <path>` разрешается относительно выбранного корня проекта;
- `--prune` удаляет устаревшие скомпилированные тесты без исходников;
- для `--prune` требуется, чтобы `outDir` был отдельным каталогом внутри
  выбранного корня проекта;
- значением `--isolation` может быть `process` или `none`;
- для `--isolation` требуется Node.js `>=22.8.0`;
- `--node-args` поглощает все последующие аргументы;
- `--node-args` должен быть последней опцией `fwa`;
- для `--node-args` требуется Node.js `>=22.10.0`;
- `--node-args` нельзя использовать вместе с `--isolation none`;
- `--help`, `-h`, `--version` и `-v` используются только как самостоятельные
  аргументы;
- `--source-dir` и `--dist-dir` не поддерживаются.

## Код завершения

`fwa` не вызывает `process.exit()` напрямую.

При ошибке выполнения или отсутствии доступных для запуска тестов он
устанавливает:

```ts
process.exitCode = 1;
```

Так жизненный цикл процесса остаётся под управлением Node.js, а раннер проще
тестировать.

## Почему не glob-шаблоны командной оболочки

Такая команда может зависеть от поведения командной оболочки:

```sh
node --test dist/**/*.test.js dist/**/*.spec.js
```

Разные оболочки и окружения могут по-разному раскрывать `**`. Из-за этого
рекурсивный поиск в npm-скриптах может различаться на локальной машине, в
контейнере и CI.

`fwa` самостоятельно обходит `outDir` и передаёт `node:test` явный список
файлов.
